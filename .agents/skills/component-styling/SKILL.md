# Component Styling & Architecture Standards

Comprehensive guide for organizing CSS classNames, managing variants with CVA (`class-variance-authority`), and writing robust Tailwind CSS v4 in the Flaner v2 monorepo.

---

## 0. Ironclad Rule: Tokens Only (Design System)

The single theme source is `packages/ui-components/src/theme/theme.css` (spec: `.agents/docs/design-system.md`). Every package `index.css` only imports it — never define tokens, `@theme` blocks or scrollbar styles in an MFE.

| Need | Use | Never |
|---|---|---|
| Subtle surface / hover / pressed | `bg-surface-subtle` / `bg-surface-hover` / `bg-surface-strong` | `bg-white/5`, `bg-zinc-900` |
| Hairline / normal border | `border-border-subtle` / `border-border` | `border-white/10` |
| Brand fill + text on it | `bg-brand text-brand-foreground` | `text-zinc-950`, `text-white` on brand |
| Brand-coloured text / icon | `text-brand-text` | `text-brand` (fails contrast in light mode) |
| Status | `bg-success|warning|danger|info` + `text-*-foreground`; text `text-*-text`; tint `bg-*-subtle` or `bg-success/10` | `emerald-*`, `amber-*`, `rose-*`, `red-*` |
| Event voting | `vote-yes|maybe|no` (+ `-foreground`, `-text`, `-subtle`, `-border`) | raw hues |
| On photos / user-chosen colours | `text-on-media`, backdrops `bg-scrim/40` | `text-white`, `bg-black/40` |
| Font sizes below `text-xs` | `text-2xs` (11px), `text-3xs` (10px); dense grids only `text-4xs` (9px), `text-5xs` (8px) | `text-[11px]` |
| Shadows | `shadow-raised|overlay|modal|edge|drawer|glow-brand|glow-warning|glow-danger|dot-warning` (or Tailwind `shadow-sm…2xl`) | `shadow-[…rgba()]` |
| Breakpoints | `xs` 360, `sm`, `md`, `lg`, `desktop` 1080, `split` 1200, `calendar` 1284, `wide` 1440 (`max-desktop:` etc.) | `min-[1080px]:` |
| z-index | numeric scale `z-0…z-50`, `z-70`, `z-100` | `z-[50]` |
| Charts | `bg-chart-1…8`, `chart-positive/negative`; in D3 read `var(--chart-N)` | hand-picked hexes |

- A surface that is always dark (e.g. calendar slot pills tinted with the event colour) gets the `dark` class on its root so every token inside resolves to its dark value — do not hardcode light colours for it.
- Data colours (event colours, filament colours, colour-picker presets) are content and stay hex values in TS.
- Enforced by `npm run lint:tokens` (`scripts/check-design-tokens.mjs`, also in CI). A deliberate exception needs a `design-tokens-ignore` comment on the line with a reason.
- Contrast of every token pair is asserted by `packages/ui-components/src/theme/theme.spec.ts`; when you add or change a token, add its pair there.

## 1. Ironclad Rule: Strict 1:1 Style Colocation

Whenever a component or view has non-trivial, multi-variant, or complex conditional classNames, **extract its styles into a dedicated `[ComponentName].styles.ts` file colocated directly next to the component**.

### Rules of Colocation:
1. **1 Component = 1 Dedicated `*.styles.ts` File**:
   - Every file with non-trivial styling MUST have its own `[ComponentName].styles.ts`.
   - 🚨 **NO JUNK DRAWER / GLOBAL STYLE FILES**: Never create shared style utility files (e.g. `votingStyles.ts`, `commonButtonStyles.ts`, `tableStyles.ts`) that hold style configurations for multiple distinct components.
2. **Subcomponents Own Their Styles**:
   - If a view has subcomponents in a subfolder (e.g. `views/SchedulerView/components/SchedulerEventHeader.tsx`), that subcomponent MUST have its OWN `SchedulerEventHeader.styles.ts` in that subfolder.
   - The parent's `SchedulerView.styles.ts` must ONLY hold styles for `SchedulerView.tsx` — it must NEVER act as a catch-all container for child components.
3. **No Cross-Component Style Imports**:
   - Independent components (e.g. `SlotEventComponent` vs `SlotMoreEventsPopover`) must NOT import style variants from each other. If both need similar styling, each defines its own variant locally.
4. **Shadcn Primitives Protection**:
   - Do NOT edit primitive files generated by shadcn CLI under `packages/ui-components/src/components/ui/*`.
   - Apply dedicated `*.styles.ts` to your own custom domain components, wrappers, and feature MFE views.

```
📁 packages/planning/src/views/SchedulerView/
├── SchedulerView.tsx
├── SchedulerView.styles.ts                    # ONLY styles for SchedulerView.tsx
└── 📁 components/
    └── 📁 SchedulerEventControlPanel/
        ├── SchedulerEventHeader.tsx
        ├── SchedulerEventHeader.styles.ts     # ONLY styles for SchedulerEventHeader.tsx
        ├── SchedulerParticipantsList.tsx
        └── SchedulerParticipantsList.styles.ts# ONLY styles for SchedulerParticipantsList.tsx
```

## 2. CVA (`class-variance-authority`) Standards

Import `cva`, `VariantProps`, and `cn` from `@flaner/shared/utils` (or `class-variance-authority`).

### 2.1 Multi-Variant & Multi-State Components
Use `cva` when styling elements with multiple variants, sizes, or interactive states (buttons, badges, cards, options, grid cells):

```ts
import { cva, type VariantProps } from "@flaner/shared/utils";

export const voteButtonVariants = cva(
  "shrink-0 p-0 border flex items-center justify-center rounded-xl cursor-pointer transition-all duration-200 font-bold select-none",
  {
    variants: {
      vote: {
        yes: "",
        maybe: "",
        no: "",
      },
      active: {
        true: "shadow-sm scale-105",
        false: "hover:scale-105",
      },
      size: {
        sm: "w-6 h-6 text-xs",
        md: "w-8 h-8 text-sm",
      },
    },
    compoundVariants: [
      {
        vote: "yes",
        active: true,
        class: "bg-vote-yes text-vote-yes-foreground hover:bg-vote-yes/90 border-vote-yes-border/60",
      },
      {
        vote: "yes",
        active: false,
        class: "bg-vote-yes-subtle text-vote-yes-text hover:bg-vote-yes/30 border-vote-yes-border/20",
      },
      {
        vote: "no",
        active: true,
        class: "bg-vote-no text-vote-no-foreground hover:bg-vote-no/90 border-vote-no-border/60",
      },
      {
        vote: "no",
        active: false,
        class: "bg-vote-no-subtle text-vote-no-text hover:bg-vote-no/30 border-vote-no-border/20",
      },
    ],
    defaultVariants: {
      vote: "yes",
      active: false,
      size: "md",
    },
  },
);

export type VoteButtonVariantsProps = VariantProps<typeof voteButtonVariants>;
```

### 2.2 Semantic Layout Objects
For components with fixed layout zones, group class names in a semantic plain object using `cn()`:

```ts
import { cn } from "@flaner/shared/utils";

export const schedulerViewStyles = {
  root: cn(
    "flex flex-col h-auto w-full max-w-[1920px] mx-auto p-0 gap-3 overflow-y-auto bg-background text-foreground",
    "sm:p-4 md:p-6 sm:gap-4",
    "min-[1200px]:flex-row min-[1200px]:h-[calc(100vh-6rem)] min-[1200px]:overflow-hidden min-[1200px]:gap-6",
  ),
  calendarPanelWrapper: "flex-1 flex flex-col relative z-10 min-w-0 min-h-[500px] min-[1200px]:min-h-0",
  controlPanelWrapper: "w-full min-[1200px]:w-[350px] relative shrink-0 rounded-3xl flex flex-col shadow-xl",
};
```

## 3. Tailwind CSS v4 & Layout Pitfalls

### 3.1 Text Wrapping: `break-words` vs `overflow-wrap`
- 🚨 **NEVER** place `break-words` inside a flex child with `min-w-0` without an explicit width constraint. In Tailwind CSS v4, `break-words` calculates min-content width down to individual syllables/glyphs, causing titles like "Ekipa testowa 1" to break into vertical 1-word/syllable strips ("Eki", "pa", "te", "st", "ow", "a 1").
- ✅ **ALWAYS** use `break-normal [overflow-wrap:anywhere]` or `truncate` / `line-clamp` for headings and titles:
```tsx
// ❌ BAD: Can cause single-syllable vertical text collapsing
<h1 className="text-2xl font-bold flex-1 min-w-0 break-words">
  {group.name}
</h1>

// ✅ GOOD: Wraps whole words cleanly while handling extreme overflow
<h1 className="text-2xl font-bold flex-1 min-w-0 break-normal [overflow-wrap:anywhere]">
  {group.name}
</h1>
```

### 3.2 Single, Unified Responsive DOM (No Duplicated Subtrees)
- 🚨 **NEVER** duplicate entire DOM subtrees using `sm:hidden` and `hidden sm:block` just to rearrange text and avatars across screen sizes.
- ✅ **ALWAYS** use a single unified element tree with responsive utility classes (`flex flex-col sm:flex-row`, `items-start sm:items-center`):
```tsx
// ✅ Unified responsive card header
<div className="flex flex-col sm:flex-row gap-4 sm:gap-6 items-start sm:items-center flex-1 min-w-0">
  <div className="shrink-0 size-20 sm:size-24 rounded-2xl ...">...</div>
  <div className="flex-1 min-w-0 flex flex-col gap-1.5">
    <h1 className="text-2xl sm:text-3xl font-extrabold break-normal [overflow-wrap:anywhere]">...</h1>
    <p className="text-xs sm:text-sm text-muted-foreground">...</p>
  </div>
</div>
```

### 3.3 Pixel-Perfect Grid & Calendar Alignment
When building multi-day calendars, event grids, or timeline rows where segments align across columns:
1. **Empty Placeholders Must Match Event Segments Exactly**:
   - If event segments use `h-[14px] md:h-[24px] mb-[1px] md:mb-0.5`, the `emptySlot` placeholder MUST use the EXACT same height and margin classes (`mb-[1px] md:mb-0.5 box-border`).
2. **Enforce `max-h` on Slot Heights**:
   - Always define `max-h` alongside `h` and `min-h`: `h-[14px] md:h-[24px] min-h-[14px] md:min-h-[24px] max-h-[14px] md:max-h-[24px]`.
3. **Constrain Inner Icons and Buttons**:
   - Interactive buttons inside small mobile slots (e.g. `X` delete buttons) must be constrained with `h-full max-h-full p-0 md:p-0.5 [&_svg]:size-2.5 md:[&_svg]:size-3` so they NEVER expand the parent row height.

### 3.4 Scrollable Lists in Sheets & Modals (Bottom Spacing)
1. **Always Add Bottom Padding (`pb-3` / `pb-4`) to `overflow-y-auto`**:
   - When a scrollable list sits above a section divider or footer (e.g. *Danger Zone* with `border-t`), lacking bottom padding causes the bottom card's border to directly collide with or overlap the divider line.
2. **Set Realistic `min-h`**:
   - For lists intended to show at least $N$ items without scrolling (e.g. 3 members in a management sheet), calculate `N * item_height + (N - 1) * gap` and set `min-h-[220px]`.

## 4. Summary Checklist for Reviewing Styles

- [ ] Does this component have its own dedicated `[ComponentName].styles.ts` in the same directory?
- [ ] Are all multi-state class combinations handled via `cva` with `compoundVariants`?
- [ ] Are there zero cross-component style imports from unrelated folders?
- [ ] Does text in flex containers use `break-normal [overflow-wrap:anywhere]` instead of aggressive `break-words`?
- [ ] Do empty placeholders in grid/calendar structures match active segments in height and margins pixel-for-pixel?
- [ ] Do scrollable containers have adequate `pb-4` bottom padding before any footer separators?
- [ ] Is the responsive layout achieved with a single unified DOM tree rather than duplicated `sm:hidden` / `hidden sm:block` blocks?
- [ ] Are only semantic tokens used (no raw palette, `white/N`, hex, `text-[Npx]`, `shadow-[…]`, `z-[N]`, `min-[Npx]:`)? `npm run lint:tokens` is green?
- [ ] Have you run `nx run <package>:lint` and `nx run <package>:typecheck` to ensure 0 errors?
